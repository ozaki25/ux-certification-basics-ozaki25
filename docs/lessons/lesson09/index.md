# lesson09: リーン開発 — ムダをなくし学習を最大化する

## このレッスンで学ぶこと

- リーン開発の考え方と「ムダの排除」という発想の由来を理解する
- リーンスタートアップの「構築→計測→学習」のループを説明できる
- MVP（実用最小限の製品）の目的を理解する
- リーンUXの特徴と、アジャイル開発との関係を整理する

## リーン開発とは

**リーン**（lean）は「ぜい肉のない・引き締まった」という意味の言葉です。リーン開発とは、**価値を生まないムダを徹底的に排除し、本当に必要なものだけを素早く作る**という考え方です。

### 由来はトヨタ生産方式

リーンの発想は、トヨタ自動車の生産方式（トヨタ生産方式）の研究から生まれました。

- 「必要なものを、必要なときに、必要なだけ」作ることで在庫などのムダをなくす
- この製造業の考え方がソフトウェア開発や新規事業づくりに応用された

### リーン開発が必要とされる理由

新しい製品・サービスづくりでは「作ったが誰にも使われない」ことが最大のムダです。

- 市場や顧客のニーズは事前の分析だけでは確かめられない
- 不確実な状況では、作り込む前に「本当に求められているか」を検証するほうが合理的
- 検証より先に大きく投資すると、間違いに気づくのが遅れて損失も大きくなる

## リーンスタートアップ

**リーンスタートアップ**は、起業家エリック・リースが提唱した、新規事業を不確実性の中で成功に導くための方法論です。中心にあるのが「**構築→計測→学習**」のループです。

```mermaid
graph LR
    A[構築\nアイデアをMVPにする] --> B[計測\nユーザーの反応をデータで測る]
    B --> C[学習\n仮説を検証し方向を判断]
    C -->|次の仮説へ| A
```

| ステップ | 内容 |
|------|------|
| 構築（Build） | アイデアを検証できる最小限の形（MVP）にする |
| 計測（Measure） | 実際のユーザーの反応をデータで測る |
| 学習（Learn） | 仮説が正しかったかを判断し、継続か方向転換（ピボット）かを決める |

このループを**できるだけ速く回す**ことで、ムダな作り込みを避けながら「顧客が本当に求めるもの」を学習していきます。

## MVP（実用最小限の製品）

**MVP**（Minimum Viable Product、実用最小限の製品）は、**仮説を検証するために必要な最小限の機能だけを備えた製品**です。

- 目的は「完成品を早く出すこと」ではなく「**最小のコストで学習すること**」
- 例: 動画1本でコンセプトへの反応を確かめる、機能を1つに絞った試作版を一部のユーザーに提供する

::: warning MVPは「未完成品」ではない
MVPは手抜きの製品ではなく、検証したい仮説に対して「実用に足る最小限」を見極めた製品です。何を学びたいのかが先にあり、それに合わせて作る範囲を決めます。
:::

## リーンUX

**リーンUX**は、リーンスタートアップの考え方をUXデザインに適用したアプローチです。

- 詳細な仕様書やデザインドキュメントなどの**成果物（アウトプット）より、学習と成果（アウトカム）に焦点**を当てる
- デザインを「仮説」として小さく作り、ユーザーで検証して学びを得る
- デザイナーだけで抱え込まず、職種を越えたチームで協働する

::: info アウトプットとアウトカム
アウトプットは「作ったもの（画面・文書）」、アウトカムは「ユーザーの行動や事業に生まれた変化」です。リーンUXは後者を成功の尺度にします。
:::

## アジャイル開発との関係

リーン開発は、アジャイル開発（[lesson08](/lessons/lesson08/)）と「反復しながら検証して学ぶ」という発想を共有しています。

| 観点 | アジャイル | リーン |
|------|------|------|
| 主な焦点 | 開発の進め方（どう作るか） | 作るべきものの検証（何を作るか） |
| 代表的な単位 | スプリント | 構築→計測→学習のループ |
| 共通する価値観 | 小さく作る・早く確かめる・変化に対応する | 同左 |

実務では「リーンで作るべきものを見極め、アジャイルで作る」のように補い合う関係として使われます。どちらも、人間中心デザイン（[lesson06](/lessons/lesson06/)）の反復の考え方と相性のよいアプローチです。

## キーワード

| 用語 | 説明 |
|------|------|
| リーンスタートアップ | 構築→計測→学習のループを速く回して新規事業を検証する方法論（エリック・リース） |
| MVP | 仮説検証に必要な最小限の機能だけを備えた「実用最小限の製品」 |
| リーンUX | 成果物より学習と成果（アウトカム）に焦点を当てるUXデザインのアプローチ |

## 試験のポイント

- リーンの由来は**トヨタ生産方式**。「ムダの排除」という発想がソフトウェア・新規事業に応用された流れを押さえる
- リーンスタートアップは提唱者（エリック・リース）と「**構築→計測→学習**」のループの順番をセットで覚える
- MVPの目的は「最小のコストで**学習**すること」。「とにかく早く完成品を出すこと」ではない点に注意
- リーンUXは「アウトプット（成果物）よりアウトカム（成果）」がキーフレーズ
- アジャイル（[lesson08](/lessons/lesson08/)）との違いは焦点の置き方。「何を作るか」の検証がリーン、「どう作るか」の進め方がアジャイルと整理する
