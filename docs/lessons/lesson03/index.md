# lesson03: UXデザインとUXデザイナー — 体験が生まれる状況を設計する

## このレッスンで学ぶこと

- 「よいUX」と「わるいUX」を分けるのがユーザー視点であることを理解する
- UXデザインの考え方（体験を直接作るのではなく、体験が生まれる状況を設計する）を理解する
- UXデザインの代表的な手法とプロセスの全体像を知る
- UXデザイナーに必要なスキルとマインドセットを理解する

## よいUX・わるいUX

### わるいUXはわかりやすい

押すのか引くのか分からないドア、注意書きの貼り紙だらけの券売機、記入欄を探すだけで疲れる申請書のように、わるいUXは日常にあふれていて、誰が見ても「使いにくい」と分かります。

わるいUXに共通するのは、**作り手の都合が優先され、ユーザー視点が抜け落ちている**ことです。

### よいUXは相対的

一方で「よいUX」は、誰にとっても同じではありません。カフェチェーンを例に考えてみます。

| 観点 | 回転重視のカフェ | くつろぎ重視のカフェ |
|------|------------------|----------------------|
| ターゲット | 時間がない人 | 時間がある人 |
| ニーズ | 隙間時間で手早く済ませたい | じっくり考えたい・仕事をしたい |
| よいUXの例 | 注文後すぐ提供・コンパクトな席 | ゆったりした席・電源・長居できる雰囲気 |

2つの店は正反対の設計ですが、**ターゲットのニーズに合っていればどちらもよいUX**です。

::: info 同じ人でも状況によって変わる
ジョブ理論（クレイトン・クリステンセン）が示したように、同じユーザーでも置かれた状況によって成し遂げたいこと（ジョブ）は変わります。同じミルクシェイクでも、車通勤の朝と休日の子どもとの時間では、求められる価値が異なります。
:::

### よいUXに共通する基準

- **直感的である**: 人の日常の判断の大半は無意識的・直感的に処理される。考えさせない設計が望ましい（背景となる理論は [lesson11](/lessons/lesson11/)）
- **わかりやすい**: 人はまとまりのある形で情報を捉えようとする。視覚的に整理された情報は理解しやすい（背景となる理論は [lesson12](/lessons/lesson12/)）
- **ユーザビリティが高い**: 有効さ・効率・満足度の観点で評価できる（詳細は [lesson14](/lessons/lesson14/)）

## UXデザインとは

**UXデザイン**とは、体験全体の質に焦点を合わせて、製品・サービス・プロセス・環境などをデザインする実践活動です。

UXは相互作用のすべてに及ぶ概念です。そのためUXデザインでは、Who（ユーザー）・What（コンテンツ）・When（時間軸）・Where（環境・状況）・How（インターフェース）という幅広い観点を考慮します。

### 体験そのものは直接作れない

ここで重要なのは、UX（体験）は**ユーザーの主観の中に生まれるもの**であり、デザイナーが直接作ることはできない点です。UXデザインの仕事は次の2つに整理できます。

- ユーザーにどんな**理想体験**をしてもらうかを計画する
- その理想体験が**繰り返し生まれる状況・仕組み**を設計する

つまり「UXをデザインする」とは、体験そのものを作ることではなく、**よい体験が生まれる状況を設計する**ことです。たとえばテーマパークは「楽しい」という感情を直接は配れませんが、アトラクションや待ち時間の演出といった状況の設計によって、楽しさが生まれる確率を高めています。

### 関連するアプローチ

UXデザインは、人間中心デザイン（HCD）（[lesson06](/lessons/lesson06/)）やデザイン思考（[lesson07](/lessons/lesson07/)）と、「現場観察の重視」「ユーザーへの共感」「初期段階で形にする」「反復的に進める」といった基本哲学を共有しています。

## UXデザインの代表的な手法

UXデザインは「リサーチ → モデリング → アイデア創出 → プロトタイピング → 評価」のサイクルで進みます。

| 段階 | 代表的な手法 | 詳細レッスン |
|------|--------------|--------------|
| リサーチ | デプスインタビュー・エスノグラフィ | [lesson18](/lessons/lesson18/) |
| モデリング | ペルソナ・カスタマージャーニーマップ | [lesson22](/lessons/lesson22/) |
| アイデア創出 | アイディエーション・ストーリーボード | [lesson24](/lessons/lesson24/) |
| プロトタイピング | プロトタイプの作成 | [lesson26](/lessons/lesson26/) |
| 評価 | ユーザーテスト | [lesson28](/lessons/lesson28/) |

このサイクルは1回では終わらず、評価で見つかった課題をもとにリサーチや企画へ戻ります。発散と収束を繰り返しながら、「正しい課題」と「正しい解決策」に近づけていきます。

## UXデザイナーとは

**UXデザイナー**は、UXデザインの一連のプロセスを実務として遂行し、成果物をアウトプットする専門職です。

### 多くの職種と協働する

| 領域 | 職種の例 |
|------|----------|
| ビジネス | プロダクトマネージャー・UXリサーチャー・UXコンサルタント |
| クリエイティブ | UXデザイナー・UIデザイナー・UXライター |
| テクノロジー | デザインエンジニア・フロントエンドエンジニア |

UXに関わる職種はビジネス・クリエイティブ・テクノロジーの3領域にまたがります。UXデザイナーはこれらの結節点に立ち、ユーザー視点で全体をつなぐ役割を担います。

### 必要なスキルとマインドセット

UXデザイナーには、UXデザインの各段階を遂行するスキルが求められます。

- ユーザー調査の設計・実施（インタビュー・行動観察）
- 調査結果のモデリング（ペルソナ・カスタマージャーニーマップの作成）
- アイデアを形にする力（情報設計・プロトタイピング）
- 検証と改善（ユーザーテストの設計・分析）

手法の知識と同じくらい重要なのが、次のマインドセットです。

- **ユーザーへの共感**: 自分の感覚で決めつけず、観察と対話からユーザーの実態を理解する
- **仮説検証の姿勢**: 最初から作りこまず、早く形にして検証し、学んだことを次に活かす
- **職種を越えた協働**: エンジニア・マーケター・経営層と共通言語を作り、周囲を巻き込む

### UXのスキルは専門職だけのものではない

UXを基軸にサービスを設計・改善する能力は、今後、ユーザーとその体験に向き合う**あらゆる職業に求められる人材要件**になるとされています。

UXインテリジェンス協会は、UX向上に必要なスキルを「UXジェネラリストレベル」「UXプロフェッショナルレベル」「UXマネジメントレベル」の3段階で定義しています。UXマネジメントはUXの統括、UXプロフェッショナルはUXデザイナーなどの専門職、UXジェネラリストはビジネスパーソン全般に対応します。UX検定基礎が確認するのはUXジェネラリストレベルで、UXやHCDの概念と一連のプロセスの基礎知識が求められます。

## キーワード

| 用語 | 説明 |
|------|------|
| UXデザイン | 体験全体の質に焦点を合わせ、よい体験が生まれる状況を設計する実践活動 |
| UXデザイナー | UXデザインの一連のプロセスを実務として遂行する専門職 |
| よいUX | ターゲットのニーズと利用状況に合った体験。相対的だが、直感的・わかりやすいといった共通基準もある |
| ジョブ理論 | ユーザーは状況に応じて成し遂げたいこと（ジョブ）のために製品を「雇う」と捉える考え方 |
| UX人材 | 専門職に限らず、ユーザーと体験に向き合うすべての職業に求められるスキルを持つ人材 |

## 試験のポイント

- わるいUXの原因は「ユーザー視点の欠如」、よいUXの条件は「ターゲットのニーズ・利用状況との一致」と整理して覚える
- 「UXをデザインする」とは体験を直接作ることではなく、**体験が生まれる状況を設計する**こと。この考え方は問われやすい
- リサーチ → モデリング → アイデア創出 → プロトタイピング → 評価のサイクルと、各段階の代表的な手法の対応を整理しておく。プロセスは一方通行ではなく**反復**する点も特徴
- UXデザイナーには手法のスキルに加えて、ユーザー共感・仮説検証・職種を越えた協働のマインドセットが必要
- UXのスキルは専門職に限らずビジネスパーソン全般に求められる（UX検定基礎はUXジェネラリストレベルに対応）
