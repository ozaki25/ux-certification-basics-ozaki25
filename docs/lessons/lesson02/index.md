# lesson02: UXが重視される背景 — デジタル化が変えたビジネスとデータ活用

## このレッスンで学ぶこと

- デジタル技術の進展が顧客接点・業務オペレーション・ビジネスモデルをどう変えたかを理解する
- OMO・D2C・プラットフォームビジネスなど、変化を表すキーワードを説明できる
- 属性データと行動データの違いと、ビッグデータ・ID統合などのデータ活用動向を理解する
- AIをはじめとするテクノロジーがUXデザインのプロセスに与える影響を知る

## デジタル技術が変えた3つの領域

スマートフォンの普及により、人々は常時オンラインで生活するようになりました。デジタルが生活の前提になったことで、企業活動は次の3つの領域で大きく変わりました。

| 領域 | 変化の内容 |
|------|-----------|
| 顧客接点 | 店舗・営業などのリアル中心から、アプリ・SNSなどデジタル接点との融合へ |
| 業務オペレーション | 人手と経験頼みの運用から、データに基づく改善・自動化へ |
| ビジネスモデル | 製品を作って売り切るモデルから、体験を継続提供するモデルへ |

この変化の結果、機能や価格だけでは差別化が難しくなり、**体験（UX）の質が企業競争の焦点**になりました。詳しいビジネスモデルの変化（バリューチェーンからバリュージャーニーへ）は [lesson04](/lessons/lesson04/) で扱います。

### 顧客接点の変化: OMO

**OMO（Online Merges with Offline）**は、オンラインとオフラインの境界が消えて融合した状態を指す考え方です。

- ユーザーは「今からネットを使おう」と意識せず、リアルとデジタルを行き来しながら行動する
- 例: アプリで注文して店舗で受け取る、店頭で商品を見てその場でECの口コミを確認する
- 企業側も「リアルかデジタルか」ではなく、**ユーザーの一連の行動全体**を最適化する発想が求められる

::: tip 「リアルにデジタルを足す」発想からの転換
OMOでは、デジタルを起点に体験全体を設計し、リアル接点を「貴重な体験の場」として位置づけ直します。チャネルごとの最適化（オムニチャネル的な発想）とは視点が異なります。
:::

### ビジネスモデルの変化: D2Cとプラットフォームビジネス

| モデル | 内容 | UXとの関係 |
|--------|------|-----------|
| D2C（Direct to Consumer） | メーカーが小売店や代理店を介さず、ECやSNSで消費者に直接販売するモデル | 顧客と直接つながるため、体験の設計とデータ取得を自社で担える |
| プラットフォームビジネス | 提供者と利用者など複数の立場の参加者をつなぐ「場」を提供するモデル（例: ECモール、配車サービス） | 参加者が増えるほど価値が高まるため、選ばれ続けるUXが事業の生命線になる |

どちらのモデルも、**顧客との継続的な関係**と**そこから得られるデータ**を前提としています。よい体験を提供できなければユーザーは簡単に離脱するため、UXの質が事業の成果に直結します。

### ユーザーとステークホルダーの広がり

デジタル化により、体験を設計すべき相手は「製品を買う顧客」だけではなくなりました。これを**ユーザーとステークホルダーの広がり**と呼びます。

- 業務システムを使う**従業員**（EXの視点。[lesson01](/lessons/lesson01/) 参照）
- プラットフォームに参加する**出品者・配達員などのパートナー**
- サービスの影響を受ける**地域社会や行政**などの関係者

UXインテリジェンス協会がUXを「企業・サービス・製品」と「関わるあらゆる人々」との相互作用と定義しているのは、この広がりを反映しています。

## 近年のデータ活用動向

常時オンラインの生活では、ユーザーの行動が大量のデータとして記録されます。このデータがUXを設計・改善するための基盤になります。

### ビッグデータと2種類のデータ

**ビッグデータ**とは、従来の仕組みでは扱いきれないほど大量・多様で、高頻度に生成されるデータの総称です。UXの文脈では、特に次の2種類を区別します。

| 種類 | 内容 | 例 |
|------|------|----|
| 属性データ | ユーザーが「どんな人か」を表す静的なデータ | 年齢、性別、居住地、職業、会員ランク |
| 行動データ | ユーザーが「いつ・どこで・何をしたか」を表す動的なデータ | 閲覧履歴、購買履歴、位置情報、アプリの操作ログ |

従来のマーケティングは属性データによるターゲティングが中心でした。行動データが取得できるようになったことで、**時間や状況の単位で顧客を理解**し、最適なタイミングで最適な体験を提供できるようになりました。行動データの分析手法は [lesson21](/lessons/lesson21/) で詳しく扱います。

### ID統合

**ID統合**とは、サービスや接点ごとにばらばらに管理されていたユーザーIDをひとつに束ね、同一人物のデータとしてつなげることです。

- 例: 店舗の会員カード、ECサイト、アプリの利用履歴を共通IDでひも付ける
- ID統合により、チャネルを横断した一連の行動が見えるようになり、体験全体の設計が可能になる
- 一方で、個人データを扱う責任が重くなり、プライバシーへの配慮と適切なデータ利用が不可欠になる

### データリテラシー

**データリテラシー**とは、データを正しく読み取り、解釈し、活用する基礎能力です。

- データ活用が専門職だけの仕事ではなくなり、企画・営業・デザインなど幅広い職種に求められるようになった
- 「データが何を意味するか」を読み解けなければ、行動データがあってもUXの改善にはつながらない
- 数値の集計だけでなく、データの背景にあるユーザーの文脈を考える姿勢が重要になる

## テクノロジーによるUXデザインプロセスの変化

**AI（人工知能）**をはじめとするテクノロジーは、UXデザインの進め方そのものも変えています。

| プロセス | テクノロジーがもたらす変化 |
|----------|---------------------------|
| ユーザー理解 | 大量の行動データをAIで分析し、行動パターンや離脱要因を発見できる |
| 体験の提供 | レコメンドなど、一人ひとりに合わせたパーソナライズを自動で行える |
| 設計・検証 | プロトタイプ作成や文章生成をAIが支援し、検証のサイクルを高速化できる |

::: warning テクノロジーは手段
AIやデータ活用は、あくまでよいUXを実現するための手段です。テクノロジーの力が強いほど、ユーザーを不当に誘導・管理する道具にもなり得ます。この問題意識は [lesson05](/lessons/lesson05/) のUXインテリジェンスにつながります。
:::

## キーワード

| 用語 | 説明 |
|------|------|
| OMO | Online Merges with Offline。オンラインとオフラインが融合し、区別なく一連の体験として設計する考え方 |
| D2C | Direct to Consumer。メーカーが中間流通を介さず消費者に直接販売するビジネスモデル |
| プラットフォームビジネス | 複数の立場の参加者をつなぐ「場」を提供し、参加者が増えるほど価値が高まるビジネスモデル |
| ユーザーとステークホルダーの広がり | 体験設計の対象が顧客だけでなく従業員・パートナー・社会へ拡大していること |
| ビッグデータ | 大量・多様・高頻度に生成され、従来の仕組みでは扱いきれないデータの総称 |
| 属性データ | 年齢・性別・居住地など、ユーザーが「どんな人か」を表すデータ |
| 行動データ | 閲覧・購買・位置情報など、ユーザーが「いつ何をしたか」を表すデータ |
| ID統合 | 接点ごとに分かれたユーザーIDを束ね、同一人物のデータとしてつなげること |
| データリテラシー | データを正しく読み取り、解釈し、活用する基礎能力 |
| AI | 人工知能。データ分析・パーソナライズ・生成支援などでUXデザインのプロセスを変えつつある技術 |

## 試験のポイント

- デジタル技術の進展による変化は「顧客接点・業務オペレーション・ビジネスモデル」の3領域で整理して覚える
- OMOは「オンラインとオフラインの融合」。チャネルを分けて考えるのではなく、ユーザーの行動全体を一連の体験として捉える点が問われやすい
- D2Cは「直接販売」、プラットフォームビジネスは「参加者をつなぐ場の提供」と、モデルの違いを正確に区別する
- 属性データ（どんな人か）と行動データ（いつ何をしたか）の対比は頻出。行動データの活用が顧客理解の解像度を高めた点を押さえる
- ID統合は「ばらばらのIDを束ねて同一人物の行動をつなげる」こと。体験全体の設計を可能にする基盤である点とセットで覚える
- AIなどのテクノロジーはUXデザインの手段であり、目的はよい体験の提供であるという関係を整理しておく
