# lesson34: 体験構造化力 — ペインの背景構造を捉える

## このレッスンで学ぶこと

- 体験構造化力とは何かを説明できる
- ペインが単独では発生しない理由を具体例とともに説明できる
- 「本来達成したいこと」と「制約条件」を分けて捉える考え方を理解する

## 体験構造化力とは

ユーザーへの理解を深めるだけでは、チームやAIに引き渡せる形にはなりません。誰が見ても同じように再現でき、根拠を説明できる形へ整理する作業が別途必要です。

ユーザーの困りごとは単独で発生しているわけではなく、置かれている状況・社会的背景・時間的制約・心理的負担・周囲との関係・使える手段の少なさなど、さまざまな要因が絡み合って生じています。

**体験構造化力**とは、こうした複雑な状況を整理し、次を構造として捉える力です。

- なぜそのペインが生じているのか
- ユーザーはどのような行動を取っているのか
- どこでつまずくのか
- 何が成功要件で、何が失敗要件なのか

AI時代にはこの力が特に重要になります。AIに何かを作らせたり、AIを活用したサービスを設計したりするには、ユーザーの目的達成までの流れをAIにも伝わる形で整理する必要があるからです。

## 目的達成の流れへの着目

体験構造化で押さえるべきは、画面や機能の名前ではありません。ユーザーや業務が目的を達成するまでの一連の流れです。

たとえば「営業支援AI」を作る場合、単に「ロールプレイングができるAI」を作るだけでは不十分です。営業担当者が本当に達成したいことは、次のような目的です。

- 明日の商談に備えたい
- 上司からの指摘を改善したい
- 自分の弱点を知りたい
- 次の一件を決めたい
- 成果を出して評価されたい

::: warning 使われなかったロールプレイングAI
ある企業で若手営業力強化のためのロールプレイングAIが作られましたが、学習データや回答精度に不足がないにもかかわらず、ほとんど使われずに形骸化しました。原因は、営業担当者の日々のノルマや上司からの指摘、商談準備に追われる状況に十分寄り添えていなかったことでした。「上司から活動を認められ、次の一件を決めるために役立つ」という方針に転換すると、「習ったことがそのまま使える」「自分の弱点が分かる」といった別の要件が見えてきます。
:::

AIの性能だけでは不十分で、ユーザーが置かれている状況と目的達成の流れに沿って設計されていなければ、AIは使われません。

## ペインの背景にある要因の絡み合い

**ペイン**とは、ユーザーが目的を達成しようとする際に感じる困りごとや障壁です。ペインは単独で存在せず、内外の要因から影響を受けて発生します。

たとえば、子どものいる家庭で食事作りを担うユーザーの「献立を考えるのが面倒」というペインを考えます。これだけを見るとレシピ提案アプリを作れば解決しそうですが、実際には共働きで料理に使える時間が短い、家族の好き嫌いがある、健康で安全な食卓にしたい、手作りが当たり前という価値観がある、といった複数の要因が絡み合っています。単なる情報不足ではなく、時間不足・気力不足・スキル不足・家族関係・社会的価値観が組み合わさって生じているのです。

## 本来達成したいことと制約条件

体験構造化では、単なる行動の連続を追うだけでは不十分で、「本来達成したいこと」と「障壁となる制約条件」を分けて捉える必要があります。

食事作りを例にすると、表面的な行動は「献立を考える→食材を買う→調理する→食卓に出す→片付ける」という手順です。しかし本来達成したいことと制約条件は、次のように分けて整理できます。

| 観点 | 内容 |
|------|------|
| 表面的な行動 | 献立を考える → 食材を買う → 調理する → 食卓に出す → 片付ける |
| 本来達成したいこと | 健康で安全な食事、家族への愛情表現、無理のない継続 |
| 制約条件 | 時間・気力・予算の不足、家族の好みの違い、毎日続ける必要性 |

本来達成したいことと制約条件を整理することで、体験の本質が見えてきます。ペイン・ニーズの関係性と、制約がそれぞれをどう阻害しているかを把握し、ジャーニーや構造図に落とし込んだうえで制約を超える方法を考えることで、理想的な体験の要件化が可能になります。

## 現状理解と理想設計の両方に必要

体験構造化は2つの場面で役立ちます。1つ目は**現状の体験理解**で、今ユーザーがどのような体験をしているかを一般性のある形に整理します。2つ目は**理想の体験設計**で、これからユーザーにどのような体験を提供すべきかを再現性のある形で立案します。

現状理解だけでは課題の把握にとどまり、理想の体験設計だけでは机上の空論になりがちです。現状を構造として理解したうえで、その構造をどう変えればユーザーが目的達成に近づけるかを考えることが重要です。

体験構造化力とは、ユーザーの状況・目的・行動・ペイン・成功要件を構造として捉える力であり、これができて初めてAIに作業を振ったり機能を実現させたりできるようになります。これらが曖昧なままでは、AIも正しくふるまうことができません。頭の中にある暗黙知を、誰もが扱える形式知に変える仕事ともいえます。

## キーワード

| 用語 | 説明 |
|------|------|
| 体験構造化力 | ユーザーの状況・目的・行動・ペイン・成功要件の関係を構造として捉える力 |
| ペイン | ユーザーが目的を達成しようとする際に感じる困りごとや障壁 |
| 本来達成したいこと | ペインの背景にある、ユーザーが本当に実現したい目的 |
| 制約条件 | 目的達成を阻む、時間・予算・関係性などの障壁 |

## 試験のポイント

- 体験構造化力は「なぜペインが生じるか」「どこでつまずくか」「何が成功/失敗要件か」を構造として捉える力である点を押さえる
- ペインは単独では発生せず、複数の内外要因が絡み合って生じるという前提を理解する
- 「本来達成したいこと」と「制約条件」を分けて整理する考え方は頻出
