# lesson29: エキスパートレビュー — 専門家目線で有効性を検証する

## このレッスンで学ぶこと

- エキスパートレビュー（インスペクション）の位置づけとユーザーテストとの違いを理解する
- ヒューリスティック評価が「経験則に基づく評価」であることを説明できる
- ニールセンの10ヒューリスティックスの項目を知る
- 認知的ウォークスルーの考え方を理解する

## エキスパートレビューとは

**エキスパートレビュー**は、UXデザインの有効性を**専門家の目線で検査・評価する**方法です。専門家による検査という意味で**インスペクション**（インスペクション法）とも呼ばれます。

[lesson28](/lessons/lesson28/) のユーザーテストがユーザー本人に使ってもらう評価であるのに対し、エキスパートレビューでは被験者を集めません。専門家が原則や経験に照らして問題を洗い出します。

| 観点 | エキスパートレビュー | ユーザーテスト |
|------|----------------------|----------------|
| 評価する人 | UXやユーザビリティの専門家 | ユーザー（被験者） |
| 時間・費用 | 被験者集めが不要なため早く・安い | 被験者収集や準備に時間と費用がかかる |
| 分かること | 原則に照らした問題点 | ユーザーの実際の行動・つまずき |
| 限界 | ユーザーの実態（実際にどう使うか）は分からない | 実施のハードルが比較的高い |

::: tip 代表的な2つの手法
エキスパートレビューの代表的な手法が、ヒューリスティック評価と認知的ウォークスルーです。
:::

## ヒューリスティック評価

**ヒューリスティック評価**は、ユーザビリティの**経験則（ヒューリスティックス）に照らしてチェックする**評価手法です。ヒューリスティックとは「経験から導かれた、おおむね正しい指針」を意味します。

評価の基準として最も有名なのが、ヤコブ・ニールセンがまとめた**10ヒューリスティックス**です。

| # | 項目 | 意味 |
|---|------|------|
| 1 | システム状態の可視化 | 今なにが起きているかをユーザーに知らせる（例: 読み込み中の表示） |
| 2 | 実世界との一致 | ユーザーになじみのある言葉・概念で表現する |
| 3 | ユーザーコントロールと自由 | 取り消し・やり直しなど、ユーザーが操作を制御できる |
| 4 | 一貫性と標準 | 表記や操作のルールをそろえ、世の中の慣習に従う |
| 5 | エラーの予防 | そもそもエラーが起きにくい設計にする |
| 6 | 再認による想起の最小化 | 覚えさせず、見れば分かるようにして記憶の負担を減らす |
| 7 | 柔軟性と効率 | 初心者にも熟練者にも効率よく使える手段を用意する |
| 8 | 最小限で美的なデザイン | 不要な情報を載せず、本当に必要な情報に絞る |
| 9 | エラーの認識・診断・回復支援 | エラーの内容と対処法を分かりやすく伝える |
| 10 | ヘルプとドキュメント | 必要なときに参照できる助けを用意する |

::: info ユーザビリティの基礎とつながる
ユーザビリティの定義や原則は [lesson14](/lessons/lesson14/) で扱っています。10ヒューリスティックスは、その原則を評価チェックリストの形にしたものと捉えると理解しやすくなります。
:::

## 認知的ウォークスルー

**認知的ウォークスルー**は、**初心者ユーザーの思考の流れを専門家がなぞりながら**、タスクを一歩ずつたどって問題を見つける手法です。

- ユーザーの目的とタスク（例: 商品を探して購入する）を設定する
- 各ステップで「初めてのユーザーは次に何をすべきか分かるか」「操作の結果を正しく理解できるか」を専門家が検討する
- 初めて使う人がつまずくポイントの発見に向いている

ヒューリスティック評価が「原則に照らした全体チェック」であるのに対し、認知的ウォークスルーは「特定のタスクの流れに沿った検査」という違いがあります。

## ユーザーテストとの使い分け

エキスパートレビューとユーザーテストは、どちらか一方ではなく組み合わせて使います。

| 状況 | 適した方法 |
|------|------------|
| 時間や費用の制約でユーザーテストが難しい | エキスパートレビュー |
| 対象範囲が狭く、被験者を集めるほどではない | エキスパートレビュー |
| ユーザーテストの前に明らかな問題を取り除きたい | エキスパートレビュー |
| ユーザーが実際にどう使い、どこでつまずくかを知りたい | ユーザーテスト（[lesson28](/lessons/lesson28/)） |

::: warning エキスパートレビューだけで完結させない
専門家の評価はあくまで「原則に照らした予測」です。ユーザーの実態は分からないため、重要な検証は最終的にユーザーテストで確かめます。
:::

## 評価結果の活かし方

レビューで見つかった問題は、すべてを一度に直そうとせず、優先順位をつけて対応します。たとえば「影響の範囲」と「対応負荷」の2軸で整理すると判断しやすくなります。

| 影響の範囲 | 対応負荷 | 優先度 |
|------------|----------|--------|
| 大きい | 小さい | 最優先。すぐに着手して改善する |
| 大きい | 大きい | 高い。スケジュールを立てて計画的に進める |
| 小さい | 小さい | 中程度。工数に空きができたら対応する |
| 小さい | 大きい | 低い。大きな余裕ができたときに検討する |

## キーワード

| 用語 | 説明 |
|------|------|
| エキスパートレビュー | 専門家の目線でUXデザインの有効性を評価する方法。専門家評価とも呼ぶ |
| インスペクション | 専門家による検査という意味で、エキスパートレビューを指す呼び方 |
| ヒューリスティック評価 | ユーザビリティの経験則に照らして問題を洗い出す評価手法 |
| 10ヒューリスティックス | ニールセンがまとめた10項目の評価基準（システム状態の可視化など） |
| 認知的ウォークスルー | 初心者ユーザーの思考を専門家がなぞり、タスクの流れに沿って問題を見つける手法 |

## 試験のポイント

- エキスパートレビュー（インスペクション）は「専門家による評価」。**早く・安く実施できるが、ユーザーの実態は分からない**という長所と限界をセットで覚える
- ヒューリスティック評価は「経験則（ヒューリスティックス）に基づく評価」。提唱者ニールセンと結びつけて覚える
- 10ヒューリスティックスは項目名を選ばせる形で問われやすい。特に「システム状態の可視化」「一貫性と標準」「エラーの予防」「再認による想起の最小化」を押さえる
- 認知的ウォークスルーは「初心者ユーザーの思考を専門家がなぞる」点が特徴。ヒューリスティック評価との違いを整理しておく
- ユーザーテスト（ユーザー目線）とエキスパートレビュー（専門家目線）の対比は頻出
