# lesson27: UXライティング — 言葉で体験をデザインする

## このレッスンで学ぶこと

- UXライティングの目的と対象（プロダクト内の言葉）を理解する
- マイクロコピーがユーザーの行動と安心感に与える効果を知る
- コピーライティング・WEBライティング・テクニカルライティング・ロジカルライティングとの違いを区別できる
- よいUXライティングの原則を説明できる

## UXライティングとは

**UXライティング**とは、ボタンのラベル・エラーメッセージ・案内文など、**プロダクトの中でユーザーが目にする言葉を設計し、体験をよくするライティング手法**です。

アプリやWebサービスでは、ユーザーは言葉を頼りに操作します。「このボタンを押すと何が起きるのか」「エラーになったが次に何をすればいいのか」といった疑問に言葉で答えるのがUXライティングです。

- 対象: ボタン・メニュー・入力フォームの説明・エラーメッセージ・通知・空状態の案内など
- 目的: ユーザーが迷わず操作でき、不安を感じずに目的を達成できるようにする
- 位置づけ: 言葉もUIの一部であり、[lesson25](/lessons/lesson25/) の情報設計におけるラベリングと地続きの活動

## マイクロコピー

**マイクロコピー**とは、ボタンやフォームのまわりに置かれる短い文言のことです。小さな言葉ですが、ユーザーの行動率と安心感を大きく左右します。

| 場面 | 改善前 | 改善後 | 効果 |
|------|------|------|------|
| 資料請求ボタン | 送信 | 無料で資料を受け取る | 押した結果（無料・資料がもらえる）が伝わり、行動しやすくなる |
| 登録フォーム | メールアドレス | メールアドレス（広告は送りません） | 入力への不安を先回りして解消する |
| エラー表示 | エラーが発生しました | カード番号に誤りがあります。再度ご確認ください | 原因と次の行動がわかり、離脱を防ぐ |

::: tip マイクロコピーは「行動の直前の不安」に効く
ユーザーはボタンを押す直前に「課金されない?」「やり直せる?」といった小さな不安を感じます。その場所に短い言葉を添えるだけで行動が変わるため、費用対効果の高い改善手法とされています。
:::

## 各種ライティングとの違い

「ライティング」と名の付く手法は複数あり、目的と対象が異なります。試験では違いの区別が問われやすいため、表で整理します。

| 手法 | 主な目的 | 主な対象・場面 |
|------|------|-----------|
| UXライティング | プロダクト内でユーザーの操作を助け、体験をよくする | ボタン・エラーメッセージ・案内文などプロダクト内の言葉 |
| コピーライティング | 広告で注意を引き、興味や購買意欲を高める | 広告のキャッチコピー・宣伝文 |
| WEBライティング | Web上で読みやすく、検索で見つけられやすい記事を書く | Web記事・コラム（SEOを意識） |
| テクニカルライティング | 技術的な内容を正確に、誤解なく説明する | マニュアル・取扱説明書・仕様書 |
| ロジカルライティング | 論理的な構成で、主張と根拠をわかりやすく伝える | ビジネス文書・報告書・提案書 |

::: warning UXライティングとコピーライティングの混同に注意
どちらも短い言葉を扱いますが、コピーライティングは「広告で注意を引く」こと、UXライティングは「プロダクト内で操作を助ける」ことが目的です。売り込みの強い言葉をプロダクト内に持ち込むと、かえって不信感につながります。
:::

## よいUXライティングの原則

よいUXライティングの条件は、**明確（Clear）・簡潔（Concise）・有用（Useful）**の3つに整理できます。

| 原則 | 内容 | 例 |
|------|------|------|
| 明確 | あいまいさをなくし、何が起きるかを具体的に伝える | 「処理に失敗しました」ではなく「通信環境を確認して再度お試しください」 |
| 簡潔 | 読まなくても流れがつかめるくらい短くする | 「〜することができます」を「〜できます」に削る |
| 有用 | ユーザーの次の行動につながる情報を入れる | エラー文に「原因」と「対処方法」をセットで書く |

あわせて、次の点も意識します。

- **ユーザーの言葉を使う**: 社内用語・専門用語ではなく、ユーザーが日常で使う言葉を選ぶ（[lesson25](/lessons/lesson25/) のラベリングと同じ考え方）
- **一貫性を保つ**: 同じ操作を「削除」「消去」などと呼び分けない。用語を統一する
- **ユーザーを責めない**: エラー時に「不正な入力です」と突き放さず、解決方法を案内する

::: info 効果はテストで確かめる
どの文言がよいかは、書き手の感覚ではなくユーザーの反応で判断します。文言を変えた2案を比較するA/Bテストや、[lesson28](/lessons/lesson28/) のユーザーテストで「言葉が理解されているか」を検証できます。
:::

## キーワード

| 用語 | 説明 |
|------|------|
| UXライティング | プロダクト内の言葉（ボタン・エラーメッセージ・案内文など）を設計し、体験をよくするライティング手法 |
| マイクロコピー | ボタンやフォームのまわりに置く短い文言。ユーザーの行動と安心感を左右する |
| コピーライティング | 広告で注意を引き、興味や購買意欲を高めるためのライティング |
| WEBライティング | Web記事を読みやすく、検索で見つけられやすく書く手法（SEOを意識） |
| テクニカルライティング | マニュアルなどで技術的な内容を正確に説明するライティング |
| ロジカルライティング | 主張と根拠を論理的な構成で伝えるライティング |

## 試験のポイント

- UXライティングの対象は「プロダクト内の言葉」であり、広告（コピーライティング）や記事（WEBライティング）と区別する
- マイクロコピーの定義（ボタンまわりの短い文言）と効果（行動率・安心感の向上）はセットで覚える
- テクニカルライティングは「正確な説明（マニュアル等）」、ロジカルライティングは「論理的な構成」とキーフレーズで区別する
- よいUXライティングの原則は「明確・簡潔・有用」と「ユーザーの言葉を使う」を押さえる
